# SU 建筑精准建模

目标：交付与可见参考一致、尺寸来源明确、墙板和洞口关系正确、隐藏部分逻辑一致且可继续编辑的建筑 SU 模型。把发现问题与修复放在 Agent 内部完成，减少用户返工；不承诺一次生成必然正确。

## 先确定可执行能力

- 沿用当前 Agent 已有的 SketchUp 连接或脚本执行方式；本 Skill 提供质量流程，不自带 MCP、SketchUp 或文件转换器。
- 检查实际可用能力：读取模型单位与几何、创建与修改对象、保存 SKP、设置相机、获取视图、剖切。不要假定工具名称或接口存在。
- 有连接时先做只读查询，确认正在操作的文档。只有脚本途径时可生成适配当前版本的脚本，但未在 SketchUp 执行前只能称为待执行脚本，不能声称已建模或已验收。
- 不把截图当作几何测量，不把脚本运行成功当作模型正确。无法验证的项目标为“未验证”，并说明需要什么能力。
- 新建项目另存独立文件；修改已有模型时保留可恢复版本，沿用既有组织方式。不要因本 Skill 自动安装连接工具或改动全局配置。

## 参考证据与尺寸基准

建模前形成精简的项目记录，保存在项目输出目录，后续随实际模型更新：

1. **参考证据**：每张图的视角、可见构件、遮挡、透视或镜头失真；平面、立面、剖面之间是否一致。
2. **尺寸来源**：每个关键尺寸标为用户给定、图纸标注、按已知基准推导或暂定，并保存来源。冲突不能静默消解。
3. **坐标与层级**：统一项目单位、原点、轴向、楼层标高，以及模型总体长宽高。
4. **构件关系**：楼板顶底面、墙体底顶、外墙定位面、洞口宿主、屋顶和女儿墙等。
5. **精细度**：按用途明确外观、墙板洞口或进一步构造细节的范围。没有说明时先交付建筑体量、墙板、屋顶、主要门窗及可见主要立面构件；不臆造隐藏配筋、机电或不可见室内。

一张透视图不能确定真实背面和绝对尺寸。优先使用用户提供的总宽、层高、轴距等可靠尺寸；不要从透视图直接按像素等比例量全图，也不要把“常见门高”当作实测基准。缺少基准时只追问影响全局的关键尺寸；用户允许自行假设后，明确采用的是比例复原模型。

对遮挡和背面采用证据最少但逻辑自洽的补全：延续已确认的楼层、轴网、屋顶排布及立面节奏。仅在有证据或用户接受时假定对称，不机械镜像主立面，不擅自增加楼梯、门窗或装饰。把推测构件单独标记，便于替换；不把推测列为真实复原。

## 用关联参数控制定位

先确认体量、楼层与结构关系，再增加细节。重要尺寸从同一组参数派生，禁止墙、板、窗各自凭图估坐标。

- 选定并记录楼层标高的含义，例如楼板顶面；不要混用结构标高和完成面标高。
- 墙体、楼板接合按项目采用的构造策略定义。若墙体从本层板顶到上层板底，则由板厚和标高派生墙高；该例不是所有建筑的通用规则。
- 外墙必须明确按外皮、内皮或轴线定位；转角、幕墙和退台继续遵循该基准。
- 门窗由宿主墙局部坐标与窗台/洞口标高定位，洞口贯穿目标墙厚；不能只贴一张面模拟已要求的真实洞口。
- 重复开间与构件使用可复用组件；变更组件定义前确认是否应影响全部实例。
- 楼梯、坡道仅在参考或任务需要时建模，先协调上下端标高、平台和洞口，再细化踏步与栏杆。
- 在组/组件嵌套及旋转缩放存在时，测量必须使用统一坐标系并累计实例变换；世界轴对齐包围盒不能替代斜墙厚度、斜屋面坡度或门洞净宽。
- 若通过 SketchUp Ruby API 执行，先核对当前官方接口及单位转换方法；内部长度与显示单位不能混淆。避免手工重复转换或猜测 API。

保持建筑、楼层、构件的可编辑组织。原始边面保留 Untagged，展示分类应用到组或组件；不要把全楼粘成无法独立修改的一团面。先建正确的主体，再创建与输出用途相关的细部；细节数量不能抵消尺度或构件关系错误。

## 三个内部检查节点

检查通过后自动继续，不要求用户逐阶段批准。只有关键参考冲突或缺少无法合理假定的输入时才集中提问。

### 1. 体量检查

在铺开门窗、装饰之前，核对总长宽高、楼层数、标高、主要退台、屋顶轮廓和主要开间。使用与参考尽可能一致的透视相机对照轮廓；尺寸检查同时使用正投影视图与数值，避免因相机差异误改几何。

### 2. 墙板与洞口检查

读取实际模型进行检查，而非重述输入参数。项目记录中保留：构件标识、检查项、实际值、目标值或关系、容差及来源、结果。

| 检查项 | 判定方式 |
|---|---|
| 单位与总尺寸 | 核对模型实测尺寸与尺寸来源；识别整体数量级和缩放错误 |
| 墙板接合 | 按既定接合策略检查墙底、墙顶及板边；识别非预期缝隙、悬空和穿插 |
| 楼层定位 | 核对同层构件及跨层构件端点标高，不只看楼层名称 |
| 洞口与宿主 | 检查实际开洞、局部宽高、墙厚穿透、窗台标高和框体落位 |
| 屋顶与退台 | 核对承接关系、轮廓和开口；缺少设计资料时不声称完成排水或结构验算 |
| 几何质量 | 检查零面积/退化几何、重复共面面、可见反面及异常细碎边面 |
| 实体质量 | 对应为实体的墙、板等检查闭合；玻璃单面、开放场地等不强制封闭 |

容差由用户要求、建模精度和参考可靠性决定，并区分几何数值容差与图像推断不确定性。不要以固定毫米阈值假装单张图片具备施工精度。

包围盒重叠只能用于发现候选冲突；用实际几何、局部剖面或接合关系确认。允许设计上有意的相交，不把墙板交接一律报错。未知构造关系先标记，不能为了“零碰撞”破坏建筑。

### 3. 多视图与隐藏面检查

检查参考视角、背面、两侧及顶面；针对墙板交接、楼梯或开口选择必要剖面。模型自检图来自实际生成模型，不使用重新生成的效果图证明建模质量。

- 对照可见部分的轮廓、楼层线、门窗数量、节奏和遮挡关系。
- 检查背面是否出现与楼层矛盾的洞口、无依据退台、悬空装饰或屋顶断裂。
- 数值合格但视觉不符时，先排除相机/遮挡/材质因素，再修改几何。
- 视觉近似但实测关系错误时，修正几何，不以参考视角看不见为由跳过。

## 局部修复和交付

把问题划为：阻止交付的关键几何错误、影响参考一致性的外观错误、可选细节，以及未验证项。自动优先修复前两类；从依赖参数或宿主关系修起，避免逐个移动实例掩盖根因。

每次修复后复查受影响构件和总尺寸；不要重复全量重建。对同一问题连续两次修复没有改善，保留最佳版本，报告原因及所缺信息，停止在该问题上盲目重试；其余独立工作继续。关键错误未解决时标为草稿，不能称“精准验收通过”。

在支持时保存后重新打开 SKP，确认文件可读取、关键对象和尺寸仍存在。若只能导出其他格式，明确实际格式与转换限制，不改扩展名伪装 SKP。

交付实际 SKP、少量必要验收视图和简明检查记录。最终说明：

- 完成的建模范围、采用的尺寸基准和精细度。
- 实际执行并通过的检查，以及未验证或未解决项目。
- 隐藏部分的主要推测，且这些推测可定位、可替换。

建筑使用尺度或规范符合性仅在任务要求且有项目地区、建筑用途及有效依据时评估；按当前权威资料核对，不把经验值或几何闭合等同于建筑合规。
